## Schema 1
Every record contains session, vessel, body, target coordinates. One capture per process, capped at 20,000 records and 32 MiB, with explicit limit message in KSP.log. Live records at 10 Hz during course correction, braking and terminal phases, 1 Hz otherwise, plus phase changes and final stop. A submitted ordinary prediction is sampled at most once per UT second; unsampled publication events have null predictionId. Correlate prediction_submit/result/published using session + predictionId, and live using predictionVersion. Unpublished results have decision and versionBeforeDecision. Stale worker results may have a submission without a result; they cannot be inferred to be published. Context change ends capture. No worker file I/O.

Each prediction sample is [ [lat,lon,radius,UT], acceptedDt, limiterDt, stepVirtualDv, cumulativeVirtualDv, surfaceSpeed, verticalSpeed, dragAccelerationAtAcceptedStepStart, liftAccelerationAtAcceptedStepStart ]. Positions are body-fixed, radius in metres. Samples every 5 simulated seconds plus first positive impulse; maximum 128, with truncation indicator. Summary counts all accepted steps regardless of sample cap. First virtual braking UT is the time at the end of the accepted step where cumulative limiter impulse first increased, NOT a physical ignition prediction. The recorded limiterDt is the existing next-step dt, not an endorsement of its use. excessDv is the sum of positive step impulses exceeding max acceleration * accepted dt by more than 1e-8 m/s. Actual steering, mass flow and engine response are not simulated by this diagnostic. No changes to timestep or limiter equations. EndpointTerrainClearance compares simulator radius with terrain queried by existing result processing; no path terrain queries or safe-touchdown guarantee. Path clearance above the input sphere can be derived from probableTerrainASL, body radius and sample radius; actual terrain profiles require separate local queries. For LANDED, contactSurfaceSpeed is simulated crossing speed, not actual landing speed. safeTouchdownValidated is always false.

Live NEU vectors are north/east/up components, thrust vector in existing KSP force units and aero vectors in m/s². Actual touchdown speed must be estimated from the last airborne sample, not the landed vessel's zero velocity. State observations use VesselState's last updated values; commanded throttle and applied throttle may refer to different physics instants.

## Acceptance and limitations
Run matched saves with capture disabled/enabled, compare phase sequence, steering, applied thrust, touchdown/impact and endpoint against normal run; instrumentation can affect timing so measure rather than assume binary-identical flight. Airless replay and unassisted Mun landing remain protected; test only equivalent conditions without RCS or minimum throttle. For Duna record full flight through terminal outcome, then compare accepted result lineage, integration start vs first impulse vs actual thrust onset, accepted/limiter dt and excess counts, aero acceleration versus time/altitude, final contact prediction vs saved vessel location. No accuracy or safe landing claim yet. Do not repair parachutes or alter control law in M1.
